# Chiptune Tracker (working name)

A touch-first music tracker for iOS and iPadOS that sounds exactly like the Nintendo DS sound hardware and exports songs as WAV/M4A audio, playable `.nds` ROMs and SSEQ/SDAT files.

Status: Milestone 1 (real-time playback on iOS). See [SCOPE.md](SCOPE.md) for decisions, architecture and milestones.

## Layout

| Path | What |
| --- | --- |
| `Core/SPU` | `DSSPU`, the DS sound hardware emulator in portable C++20. Driven only through the real hardware registers. |
| `Core/Engine` | `TrackerCore`, the real-time engine: transport, song ticks, lock-free commands and telemetry. Also the hardcoded demo song. |
| `Core/EngineC` | `TrackerEngineC`, a C interface to the engine so Swift can use it without C++ interop. |
| `Apple/TrackerAudio` | `TrackerAudio`, AVAudioEngine playback, the audio session and telemetry for SwiftUI. |
| `App` | The iOS/iPadOS app. `App/ChiptuneTracker.xcodeproj` is generated by `scripts/generate-xcodeproj.py`. |
| `Tools/spu-render` | Renders the demo song to WAV offline. |
| `Tools/realtime-check` | Plays the demo in real time on a Mac and checks render timing. |
| `Tests/CoreTests` | Unit tests for the SPU and engine. |

## Build and test

Requires Xcode with the Swift 6 toolchain. No other dependencies.

```sh
scripts/test.sh                                       # unit tests
swift run -c release spu-render                       # render demo-all.wav
swift run -c release realtime-check --seconds 5       # real-time check on this Mac (add --mute for silence)
open App/ChiptuneTracker.xcodeproj                    # the iOS app
```

To run on a device, pick your team under Signing & Capabilities. The `-autoplay` launch argument starts the demo on launch.

After adding or removing files in `App/Sources`, regenerate the project with `scripts/generate-xcodeproj.py`.

## Real-time audio

The engine renders at the DS's native ~32,728.5 Hz. An `AVAudioSourceNode` pulls from it on the audio thread, and AVAudioEngine resamples to the hardware rate. The render path doesn't allocate or lock:

- UI commands reach the audio thread through a lock-free single-producer/single-consumer queue.
- Telemetry comes back through atomics.
- A unit test counts heap allocations across 500 render callbacks of varying sizes and requires zero.

The render closure is created in a `nonisolated` function. If it's created inside a `@MainActor` method, Swift 6 makes the closure main-actor isolated, and it traps when CoreAudio calls it on the audio thread.

## Hardware accuracy

The SPU is written from GBATEK's DS sound documentation. Where GBATEK is ambiguous (for example, PSG duty 7 and start-up delays), behavior was checked against melonDS by observation only. No melonDS code is used, so the core isn't bound by the GPL.

Not emulated yet: the two capture units, SOUNDCNT output routing, the hold bit, and SOUNDBIAS (the standard 0x200 is assumed).
